## Architecture and non-negotiable engineering controls

- Target **C17 native core + versioned .a/.so/public ABI**, Rust/Axum application and safe FFI, Nuxt/Vue/TypeScript browser UI; Ubuntu 24.04/Linux and containerized verification. Existing legacy Python tooling/backend may remain **only** during verified migration; **no new Python/FastAPI/Celery/Redis/PostgreSQL path** or speculative services for the target product. Keep Native/C/Rust/server concerns separate from browser-local Free features.
- Correctness → security → reliability → measured performance → cost. Validate untrusted file bytes, format, dimensions, decoded pixels, metadata, sizes, paths, lifecycle and resource bounds at **each trust boundary**. Browser-local Free images must **not upload by default**. Server-side images and temporary data require isolation, size/CPU/RAM quotas, cancellation, failure cleanup, redacted diagnostics, and no permanent image storage by default. Never print or commit secrets, production images, credentials or customer data.
- C/Rust unsafe/FFI must have explicit ownership, lengths, bounds, lifetime, concurrency and ABI/version checks; unsafe localized, no unproved `Send/Sync`. Preserve old ABI behavior unless a reviewed migration establishes parity. Do not assert SIMD/nanosecond gains, throughput, safety or 1 GiB VPS readiness without reproducible evidence. **P8 PowerShell harness is source-broken** until a separate parser-tested repair; P14 actual-host TLS, isolation, resource and rollback gates are not proven by Docker simulation.
- Keep changes small and modular (SOLID/DRY without overengineering), with HLD/LLD, design pattern or DSA analysis **only when the affected boundary merits it**. No premature Kubernetes, queues, DB, observability stack or paid hosting. Source contracts: [technology policy](docs/TECHNOLOGY_AND_REPOSITORY_POLICY.md), [architecture](docs/architecture.md), [security](docs/security.md); load relevant docs **on demand**, not all at startup.

## Testing, Git, evidence and approvals

- Before coding: detect stale worktree, impacted boundary, prerequisites, minimal test lane, failure/rollback case. For frontend, check Nuxt generated files, build artifact and Playwright/browser availability **before** expensive E2E runs. Diagnose setup failures explicitly; never misreport an environment block as a test pass.
- Use focused local tests during iteration, then a coherent final verification at the tested commit. Preserve the repository's **seven required GitHub PR CI jobs**, native build/sanitizer/fuzz/FFI gates when relevant, privacy/accessibility tests and exact-head SHA evidence. Do **not** weaken CI or skip affected checks to save Codex usage.
- Review `git diff`, whitespace, credentials, source tests and docs. **Committing locally may be appropriate; do not push without explicit owner approval.** Do not force-push, rewrite remote history, merge, deploy, publish subscriptions, change DNS/keys, buy cloud capacity or change billing settings without the relevant separate authorization. A docs PR never means a feature or product is released.
- Update the **short `next.md`** with factual task state/PR/check/merge SHA once confirmed. `PR_OPEN` is not `MERGED`; `MERGED` is not `RELEASED`. After an external merge, reconcile the board in the next *authorized* change. Limit green handoffs to about 8–12 lines and give the next actionable milestone.

Apply these **as checks, not verbose personas**: junior (correct behavior), mid (integration), senior (tests/maintainability), lead (delivery/dependencies), staff (module boundaries), principal (concurrency/performance/system safety), CTO (product/roadmap/architecture/operational cost). For **relevant** tasks also assess security/SRE threat and recovery, financial unit economics (hosting, bandwidth, price, tax/refunds when applicable), MBA/customer value, management sequencing, and explicit assumptions/counterexamples.
