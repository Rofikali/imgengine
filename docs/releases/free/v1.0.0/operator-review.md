## Monthly Gmail review

Rofik Ali owns the support mailbox. This proposed manual procedure requires approval and a rehearsal with synthetic messages. The Gmail account also receives unrelated mail. Apply a dedicated IMGENGINE support label to verified incoming and outgoing correspondence. Each month inspect labelled conversations across All Mail, including sent and archived messages. Check for missed replies and attachments. Archiving only removes the inbox label. For each case record the last interaction and its 12-calendar-month anniversary. Schedule cases expiring before the next review for action on their due dates. An old first message does not establish that the whole thread has expired.

For a verified earlier deletion request or unnecessary sensitive attachment, identify the specific messages and copies, including forwarded or downloaded copies where controlled. In Gmail an attachment belongs to its message. Review the enclosing message before removing it. Check for an active case, verified requester, documented legal/security hold, or other legitimate exception. Record scope, reason, owner and review date privately. After explicit operational authorization move only the selected messages to Trash. Record counts and completion date without message contents. Never publish correspondence. Until the procedure is rehearsed and assigned, the 12-month target is a proposal.

Gmail normally removes trashed messages after 30 days. Recovery through Trash ends on permanent deletion. Google operates backups on a separate lifecycle. Do not promise a backup erasure date or empty Trash during review. A mailbox integration is unnecessary for this manual procedure. ## Engineering boundaries

The Free target is the generated static tree. Native C, Rust HTTP, FFI and server processing are outside the deployable archive. CI exercises malformed input, tool limits, browser export, mobile viewports, accessibility and network/storage assertions. Device memory and elapsed time vary with resolution and browser. A numeric performance guarantee requires separate measurements. The generated header policy includes CSP script hashes, nosniff, no-referrer, framing and permissions restrictions. HSTS is a live host decision, particularly for subdomains and preload. Before announcing release run the [live smoke record](CLOUDFLARE_LAUNCH_GATE_AND_SMOKE_TEST.md), including a real edit/export and private-network inspection on each supported browser. Reconcile the shipped JS and its third-party notices against the candidate dependency inventory before final freeze.
