# Retired — PR-driven milestone documentation automation

**Retired by owner direction on 2026-11-21 (subject to review/merge of the replacement).** The former automation read GitHub pull-request and CI status to generate `next.md` and `docs/engineering/live-status.md`. The owner requires a different design: the Codex agent or software engineer who performs each change must directly maintain engineering status, decisions, tests and documentation **while doing the work**.

The retired implementation included `.github/workflows/milestone-status-sync.yml`, `.github/workflows/milestone-status-tests.yml`, `scripts/milestone-sync.mjs`, `scripts/milestone-sync.test.mjs`, `scripts/milestone-status-publication.mjs`, and `scripts/milestone-status-publication.test.mjs`. These files are proposed for deletion in the same bounded change. No `pull_request_target`, `push`, scheduled, or dispatch event should be allowed to generate documentation or create a bot branch/PR. **Do not re-enable these triggers** or ask the owner to grant Actions PR-creation permission for status updates.

**Historical diagnosis:** GitHub Actions status sync run [#44904194415](https://github.com/Rofikali/imgengine/actions/runs/44904194415) failed because Actions was not permitted to create pull requests, leaving generated status stale. The correct remedy for this owner's workflow is to retire PR-derived reporting, **not** to bypass permissions or auto-merge docs.

**New authority:** [Agent-owned documentation and work-states contract](DOCUMENTATION_SYNC_CONTRACT.md), [live manual work board](../../next.md) and [agent-maintained activity log](live-status.md). A PR may carry implementation for review; it is not the trigger, author, or truth source of task progress. Use actual modified files, tests, and acceptance evidence. Free release gates remain unchanged.
