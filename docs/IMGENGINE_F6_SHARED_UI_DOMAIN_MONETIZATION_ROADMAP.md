## HLD and LLD direction

One Nuxt/Vue/TypeScript design system; semantic HTML5, native CSS custom properties, Grid/Flexbox, system fonts, small inline SVGs; minimal JS for necessary interactions. No new CSS/UI framework, global store, external fonts, animation library or backend without an evidence-backed ADR. Shared tokens (color, spacing, typography, radius, focus/status); shared shell (header/navbar/dropdown/footer), UI primitives, file selection/preview/status components and page sections; product configuration supplies links and availability; product layouts compose them. Keep actual image-processing logic, entitlements, credentials and privacy notices separate. Existing C17/Rust/FFI and legacy routes remain intact. Keep Free route allowlist, empty server directory, CSP, no-upload and compiled static artifact audit fail-closed. No silent server fallback. Use shared components in current frontend first; extract a Nuxt Layer only once a second real app needs it; independently version a package only if justified. One brand, independent product build/test/release; no permanent branch proliferation.

Suggested incremental structure: assets/css/tokens.css and base.css; scoped component styles; components/shell and ui; layouts; config/navigation and products; features and composables when actual reuse exists. Avoid bulk folder rewrites. Header: Home, Tools disclosure, Products (clearly planned where unavailable), About/Contact. Native details/summary with keyboard Escape/focus restoration, touch, active links and no-JS basic navigation. Footer: tools, company, support, privacy, terms, licenses; no deceptive availability. About and Contact static pages; use monitored email/support initially, no new contact backend. Add only explicit routes and update prerender allowlist, static verifier, route/security tests and notices together. Consistent select/configure/process/download UX, usable on mobile and accessible keyboard/screen reader. Light/dark via tokens only after baseline; avoid duplication.
